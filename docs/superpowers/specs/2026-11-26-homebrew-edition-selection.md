# Edition selection in CYTV Installer on the TV

Design for review, based on `edd4053f`. On a fresh TV, offer Root by default. Offer a reduced-function No-root installation only after the Installer establishes both that ordinary Root cannot run on this TV and that it can complete the No-root workflow. A person still confirms installation and approves TV pairing. An existing product or operation opens its own status or recovery flow first.

The owner selected the GitHub-account namespace for the candidate, `io.github.razdva122.cytvinstaller`. The earlier `com.cleanyourtv.installer` package has a distinct app identity. Keep each candidate's app-originated tests, package paths, operation evidence and hashes attached to its actual ID. [Candidate acceptance](../../development/HOMEBREW-INSTALL-ACCEPTANCE.md)

## How the desktop decides

The desktop CLI admits an alternative in two narrowly defined situations.

| Observed evidence | Desktop decision | On-TV implication |
| --- | --- | --- |
| Ordinary Root fails its Node check and a separate read returns an exact, valid Node version below 8 | Evaluate No-root. Exactly `v0.12.2` can also offer separately packaged, opt-in Root Beta. | The current TV bootstrap itself needs Node 8+. A generic bootstrap failure cannot identify an old runtime. Route these TVs to the computer or Android workflow until a supported reader and installer can run on them. |
| The System Profile service is positively absent and the supported alternate Root backends were evaluated | Desktop offers No-root only for the typed `NoRootAlternativeError`. The two current cases are unavailable native Home and a positively identified legacy LG Home ribbon. | Preserve the same predicates and precedence, including supported compositor backends. A backend supported by desktop but missing from the TV package is a delivery limitation. Offer the supported Root route on the computer. |
| Missing information, timeout, generic rejection, blocked Homebrew access, unsupported installer ABI, invalid package or an interrupted operation | No automatic edition transfer. | Display the specific prerequisite or recovery action and allow inspection again. |

For the native Home case the capability reader distinguishes an explicit unavailable result from a failed read. It also accepts a rejected KeyFilters request accompanied by independent positive evidence of native Home unavailability. For the ribbon case KeyFilters must be absent or unconfigured and the compositor's ribbon read must return exactly one Home entry with boolean visibility. The classifier first admits any supported embedded backend. A diagnostic label such as `root-home-unsupported` covers more results than the exception that actually triggers the edition offer. Use the admission decision from the shared classifier.

The desktop uses a fresh alternative profile with the existing authorized Root SSH connection. It requires an idle device operation, no retained Root conflict, supported ARM32 userland on a compatible kernel, TV Node 0.10.15 or later, clear Root routing, and stopped or positively identified stale Helper state. It verifies the UHD capability and matching Home IPK at 1920×1080 or 1280×720, verifies Helper and any declared Ambient companion, and checks private observer storage and capacity. It checks capacity again with the personalized bytes before submission. A verified Root clean-removal handoff has its own protocol. A fresh fallback may not consume that receipt as if the device were empty. ## TV installer at the design baseline

The app uses the existing Homebrew bridge to inspect Root and drive its fixed product operations. The bootstrap requires authorized execution and Node 8+ before dispatch. Its outer failure and the device classifier both have broad `unsupported` states. The existing Root device preflight checks the product ABI and Home interfaces. Its installed-state inspection cannot provide the independent Home capability and fallback admission verdict above. Catalog metadata still requires a rooted TV, including for an eventual No-root product installation through this route. [Fixed bridge](../../../homebrew/app/bridge.js) · [Bootstrap](../../../homebrew/bootstrap.js) · [Local device checks](../../../root-edition/install_device.py) · [Homebrew Channel 0.8.0 release notes](https://github.com/webosbrew/webos-homebrew-channel/releases/tag/v0.8.0)

The offline payload contains Root, Root Updater, System Updater and the runtime. The package does not contain the two No-root Home variants, Home Helper or the No-root installation plan. Root's generic local inventory supplies app data for Root personalization. The Helper's on-TV inventory reader requires an existing SSAP client key and stops if fresh pairing is needed. The desktop client can initiate an owner-approved SSAP registration and read apps and inputs. Installing IPKs through a package service would leave pairing, configuration, recovery and the final readback unresolved. ## Proposed interaction and implementation

1. **Inspect the current installation.** A matching active operation takes priority over a new setup. For a fresh device, reuse the desktop capability classifier against a bounded, read-only local adapter. Present Root when its requirements and the selected artifacts match. Reserve separate outcomes for confirmed Root incompatibility, an inconclusive check, a missing installer capability, and recovery. Bind the reviewed edition, component identities, graphics variant and package digests to the operation. Revalidate them and the live blockers at submission.
2. **Review No-root only when eligible.** Verify the alternative preflight and package inventory before displaying the option. Show the reason Root is unavailable, the component versions, and the effect of using Home Helper for Home routing. Offer “Install No-root” and “Cancel”. The Root-only supervisor and activation controls have no role on this screen. An unknown check or a missing facility leads to guidance for the established external installer.
3. **Pair on request.** A fixed on-device facility would need to initiate the normal TV SSAP prompt for its own registration and handle acceptance, rejection, cancellation and timeout. Keep the credential and inventory inside the private installation workflow. The UI gets progress and the outcome. Only an explicit retry may request pairing again. Use the same permission set, inventory validation and documented missing-input policy as the desktop. Prove on representative firmware that the owner can see and accept the real prompt while the installer is open, and that Helper can use the resulting key.
4. **Deliver and recover the selected edition.** Authenticate both No-root Home variants, `com.local.nativehome` and any declared `com.cleanyourtv.screensaver` in the offline manifest. Verify app identity, resolution, version, integrity and size before choosing the matching `com.gathin.tvhome`. Reuse desktop personalization, package order, version and file readback, and verified Helper configuration. Port the existing original-stream observer and private recovery capsule semantics to an authorized on-device client. The desktop keeps part of that evidence on the computer. Define durable ownership independent of the Installer application's lifetime before enabling submission. Status, resume, cancellation and removal must recover the same operation after a UI close, restart or caller change, with explicit handling of lost terminal evidence. Respect Helper's stop generation, emergency release and any saved prior operation.
5. **Report what was observed.** Distinguish package/configuration readback, launch acknowledgement, observed Helper process and verified Home routing. Display the best established result and permit recovery or an explicit start where appropriate. The physical remote, standby, cold boot and rollback require their own observations.

The current TV package exports no complete No-root admission, first-pair, install or recovery operation. Implementing the capability judgment and honest status screens is feasible independently. A selectable installation requires the payload, supported pairing flow, edition-aware lifecycle and acceptance above. Keep access denied or unverified at the existing prerequisite screen and preserve its saved request ID. The design requires no new general command interface or changes to Homebrew permissions.

The development implementation now runs the shared read-only Home classifier on fresh setup and after verified clean removal. It points to the computer or Android installer when a supported Root backend is available only there, or when Root Home is positively unavailable and external setup can check No-root. An inconclusive reading exposes only status and guidance. On old Node runtimes the fixed bootstrap can report the Node prerequisite before loading the modern runtime. The local No-root action remains unavailable. The Helper's inventory reader requires a previously registered controller, and a supported owner-approved first registration originating on the TV has yet to be established. ## One confirmation for Root installation and activation

The proposed fresh Root action is **Install and activate Root Home**. Its review screen names the candidate components and explains that Home will route to CYTV after setup. Record that approval under the exact installer identity, reviewed candidate digest, install operation ID and intended product generation. Where the product assigns its generation at installation, bind it from the verified original install receipt. A later reinstall of identical package bytes starts a different generation and needs its own approval.

1. Complete installation under the existing product mutex. Persist its completion and verify current package and recovery state. Release the install mutex before starting a separate activation operation. Closing or reopening the UI must preserve the same installation and activation records.
2. Under the activation operation's serialization, match the original approval and completed install to the current product generation, recheck recovery and emergency state, then durably claim the one permitted enable attempt before dispatch. Competing callers observe the same claim. Stop if the candidate, generation or operation has changed.
3. **Restore LG Home** cancels outstanding activation consent for that generation. Serialize Restore with the activation claim so an earlier consent cannot enable Home after Restore. If enable is already in flight, reconcile that attempt and verify the final restored route. Removal, replacement or an emergency stop must also prevent a deferred activation from rearming Home.
4. A lost reply leaves a claimed attempt. Reopen or retry reads its original record and current device state. Never replay enable solely because the acknowledgement is missing. When the readback cannot establish completion, show “Installed, activation unverified” and keep Restore available. Any subsequent activation request requires fresh owner intent and resolution of the earlier attempt.
5. Mark activation complete only after reading the current generation, the selected backend's enabled state and expected Home routing. The setup result distinguishes installation from activation. An end-to-end Home check records the foreground destination after an actual Home input. [Product coordinator](../../../root-edition/install_driver.py) · [Device adapter](../../../root-edition/install_device.py)

Exercise cancellation between install and activation, concurrent Restore before and after the enable claim, lost replies on either side of dispatch, reopening an interrupted request, and replacement by an identical-version generation. Each case checks the resulting Home route and the number of enable submissions. These are acceptance cases for the proposed workflow.

## Verification scope

Exercise a supported Root backend, each affirmative incompatibility predicate and inconclusive lookalikes. Cover blocked access, old Node, supported Root available only through desktop, retained state, mixed receipts, insufficient space, graphics variants and a damaged package. For the proposed TV adapter, add cases for prompt rejection and successful first pairing, cancellation, restart before and after package submission, package terminal failure and readback drift, persistent emergency stop, external client handoff and product removal. Require product and Home-routing evidence on a TV that independently satisfies the fallback predicates.

At the design baseline, 103 existing offline tests passed with the project Python environment. The 54 tests in `test_root_capabilities`, `test_root_preflight` and `test_root_runtime` cover Root admission and retained state. Ten selected CLI tests exercise version and Home fallback, including refusal and storage failures. The 39 tests in `test_tv` and `test_graphics` exercise desktop pairing, inventory and graphics. These are desktop and fixture results. On-TV edition selection, first pairing, installation and recovery await implementation and device evidence.
