# One Homebrew package for No-root Home

This proposal uses one TV tile containing the existing Home web interface and a JavaScript service registered under the same application ID prefix. The service owns pairing, installed-app discovery and optional startup. The user installs one resolution-appropriate IPK in stock Homebrew Channel and finishes setup with the remote. The starting point is a TV with an active Developer Mode session and a working Homebrew Channel. Installing Homebrew Channel or renewing an expired Developer Mode session is a separate operation.

## Owner experience

1. Install and open **Clean Your TV Home**. The first screen offers **Pair with this TV** and **Later**. The service requests native LG consent only after the owner selects Pair. Before the first request, explain that approval also starts the service when the TV turns on. Declining returns focus to Try again and leaves the startup preference unchanged.
2. After approval, show the first usable application grid. A fresh grid can populate once from verified launchable applications. An existing or deliberately empty layout keeps its selection and hidden entries. **Show installed apps on Home** lets the owner populate it explicitly. If reading applications fails, show Retry and keep Settings reachable.
3. Register background startup after the first successful pairing on a fresh installation. Keep Stop and manual enable in Settings. Preserve the startup preference of previously paired installations, including older versions with startup off. Show distinct states for paired, waiting for startup confirmation, enabled and stopped. A service waking in the background can leave HDMI visible. Make any option that changes the foreground explicit and independently test it.
4. **Turn off automatic startup** invalidates pending activation before cancelling the service's own scheduled work. **Pair again** requests fresh LG consent and keeps the last working configuration until the replacement is verified. Reopening the tile, updating the IPK or receiving an old callback preserves an explicit Stop.

## First visible screen after HDMI

With automatic startup enabled, switch to HDMI, turn the TV off with the remote and turn it on again. Clean Home's app grid must be the first visible application or input screen. Seeing LG Home or HDMI even briefly fails this case. Stop must still prevent automatic presentation after pairing again. Record remote standby separately from a software restart or loss of mains power.

The [desktop No-root startup handler](https://github.com/Razdva122/clean-your-tv-lg-webos/blob/e9def6f2b3fa8a8469bfe2129c77f79d3cc37d84/native/app/native.js#L368-L389) inspects the existing foreground and requests Home when it finds LG Home or the system cover. It preserves a detected HDMI foreground. The [standby handler](https://github.com/Razdva122/clean-your-tv-lg-webos/blob/e9def6f2b3fa8a8469bfe2129c77f79d3cc37d84/native/app/native.js#L1491-L1508) also reads the restored foreground and accounts for LG Home appearing briefly. Copying those handlers cannot establish first-screen selection. The single-package pilot currently schedules its background service. Its callback receipt establishes when the service ran.

Before claiming first-screen support in either installation channel, identify a way for webOS to select Clean before presenting the saved input. Compare the same edition and power settings. Observe the panel continuously from power-on to the populated grid to establish the absence of any intervening picture. A sampled foreground ID or the time of a successful launch cannot exclude a brief HDMI screen.

## Package and trust boundary

Use the existing Home packaging path as a starting point. It already builds a web app with a package-prefixed service. For the hardware pilot select a distinct development application ID, derive the service ID from it and publish one card in a private QA feed. Do not reuse a production ID for the pilot. Derive the UI RPC destinations, service constructor, sender checks, catalog queries and activity callback from that identity. Inspect the built payload for active production references, then exercise the actual settings and launch controls with no legacy Helper installed. Public identity, component migration and signing are release decisions. The old native Helper, Root installer and third-party Home Chooser have no role in first setup. LG documents packaging a web app and JS service together. [LG JS service guide](https://webostv.developer.lge.com/develop/guides/js-service-usage)

Use narrow same-package service methods for status, pairing, catalog, enable and disable. Authenticate the web application's identity from the platform's message envelope before accepting a change or disclosing app inventory. Treat ordinary app-launch parameters as navigation only. The service requests pairing with the local TV, keeps the credential out of UI responses and diagnostics, and returns only the display data the grid needs. Serialize requests and invalidate pending work on cancellation, Stop or replacement. A late response must not enable a stopped installation. [LG service message reference](https://webostv.developer.lge.com/develop/references/webos-service-reference)

Prove durable private storage from the actual packaged service before accepting a real TV credential. LG documents Keymanager3 from webOS TV 24. On compatible firmware, evaluate a service-owned Keymanager3 key for authenticated encryption of a persisted credential. Exercise a harmless test value across service exit, restart, update and cold boot before pairing. If no private store is verified, explain this in Settings before offering a pairing prompt. Keep manual navigation available and leave credential-dependent features disabled. Keep the application's inventory and layout separate from the credential. [LG Keymanager3 reference](https://webostv.developer.lge.com/develop/references/keymanager3)

After a first successful pairing with the default preference, or a manual enable, the service registers one named persistent activity using the documented public Activity Manager interface. Verify its returned ID and authentic delivery to the bundled service, including delivery after rescheduling. The service must tolerate termination between callbacks. Authenticated callbacks reschedule while enabled. After Stop, late deliveries do no work and do not rearm. Keep durable intent, Stop and deduplication state, and verify a later boot independently before reporting boot acceptance. Test repeated installation and scope schedule replacement to the current service's own activity. [LG Activity Manager](https://webostv.developer.lge.com/develop/references/activity-manager)

## Home button, coexistence and rollback

LG describes Smart Home as a system key. No supported global Home reassignment for a background JS service has been established in this design. The everyday launcher must work from its tile. Expose system Home replacement only after identifying a supported platform integration and proving it with the physical remote outside the app. Pairing and background startup do not establish global key routing. [LG Magic Remote guide](https://webostv.developer.lge.com/develop/guides/magic-remote)

Keep existing Root and desktop/Android installations working. Before offering ownership of routing, identify a competing active Home integration and direct the owner to its normal Stop control. Leave existing credentials with their owning package. A later migration can offer an approved preference import and fresh pairing. Test disabling and removing the new package through Homebrew, preserving stock LG Home, then reinstalling with a stale own activity. Check that uninstallation and Developer Mode expiry leave ordinary TV navigation usable.

## Proposed hardware acceptance

| Case | Evidence required on the selected single IPK |
| --- | --- |
| ONE-01 Package and authority | One HBC Install produces one visible tile and its own service. Record ID, version and hash. The actual screen can read status; only the authenticated owner UI can change setup. |
| ONE-02 Private state and consent | Verify service-owned storage across restart, then observe LG refusal, retry and approval with the physical remote. Verify that Later, refusal and cancellation leave the fresh installation off and that approval requests startup once. Check revoked-key recovery. |
| ONE-03 Daily Home | A fresh Home shows real app tiles and can launch one. Reopen it; verify a saved layout, a deliberately empty layout, and the explicit restore action. Record counts without app inventories. |
| ONE-04 Startup and Stop | Observe the service's own scheduled callbacks, including after service exit. Stop wins over pending and stale callbacks. Pair again and update after Stop. Confirm that only manual enable resumes startup. |
| ONE-05 Wake and boot | Record standby/wake, verified software restart and an AC cycle separately. Use a boot-scoped receipt of a real Activity Manager callback that predates the first UI launch and status query, or a passive observer. A status request can start an idle JS service. Record the initial foreground independently. |
| ONE-06 Home and recovery | With the manual launcher the expected destination from Media Player is stock LG Home for both the network remote and a single physical Home press. If a supported global integration is added, verify its distinct custom destination and physical emergency release to LG Home. |
| ONE-07 Lifecycle | Exercise update, disable, HBC removal, clean reinstall and recovery with a retained failed own schedule. Verify stock Home and absence of unintended foreground launches. |
| ONE-08 Unrooted permission boundary | Repeat ordinary install, pairing, persistence, startup and removal on a genuinely unrooted Developer Mode TV. A No-root global routing claim also requires custom physical Home from another app and emergency return to LG Home on this same unrooted device and exact IPK. |

Start with ONE-01 and the harmless storage and callback checks. Those determine whether the core design is viable before introducing live credentials or asking for physical actions. A usable manual launcher and verified background startup can be reported independently. Publication claiming global Home replacement or No-root support requires the corresponding evidence. This document specifies future tests and makes no compatibility claim.
