# Issue #687 IR Home routing

## Evidence and scope

The original public report covers LG 43UP751C0ZF, firmware 03.53.45,
SDK 6.5.3, No-root, Windows AMD64 installer 0.21.0. The exact Helper and
remote model were unknown. One press from YouTube produced a Home launch
request at +802 ms, an accepted reply at +1527 ms, CYTV foreground at
+3036 ms, then LG Home at +5154 ms. A second press from LG Home retained
CYTV until the capture expired.

A separate [public observation](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/687#issuecomment-7134713915)
covers LG 55UQ75006LF, firmware 04.60.92, SDK 7.6.0, No-root,
Helper 0.8.0 and Home 1.14.0. Installer platform and exact remote model
were unknown; the input was recorded as IRHOME. The owner reported a local
guard working for over a week, with an approximately 0.3-second LG Home flash
in a warm launch and a longer black transition after reboot.
The supplied excerpt does not establish all request and foreground timestamps.
Its description of a 1–2-second transition during the IR timer differs from
the current 700 ms delay.

The associated [#818](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/818)
identifies slow launch acknowledgement and worker termination. This change
addresses the manual launch timeout and IR routing. Background Home residency
and the proposed keepAlive manifest change remain separate work.

## Implementation and checks

The existing foreground subscription can end the 700 ms fallback early when
LG Home appears. An IR press also starts a ten-second recovery window. It
permits at most two retries, waits at least 600 ms of continuous LG foreground,
and uses a six-second request cooldown until CYTV has been observed.
Each retry resets that observation. The existing 400 ms controller tick
evaluates the guard.

The guard is canceled by new app navigation, Back, explicit LG Home, Home
dismissal, disabling routing, Stop, input loss, emergency release, monitor reset
and inactive power. A Magic Home press cancels the IR guard.

Manual Home activation has a fifteen-second acknowledgement deadline.
An unconfirmed timeout records a failure and retains input routing.
Explicit rejection or an unresolved owned-window close still releases the
worker. Terminal input cleanup keeps its existing short deadline and refuses
a final LG launch while an owned launch is pending or unknown.

All 135 controller/resume/watchdog tests passed. The existing IR, Home,
keep-source, resume, Home-control and native prototype checks passed, along
with compiled Helper ES5 compatibility and runtime checks on host Node
v23.11.0. The Linux-only multi-UID check was skipped on this macOS host.
Virtual-clock cases replay the original late takeover, warm recovery,
cold launch, bounded retries and cancellation. Device acceptance is pending.
Visible LG Home flashes and system black transitions can still occur.
No TV was changed or tested in this implementation task. Physical IR,
Magic Remote, emergency release, sound, standby and cold boot remain untested
on the selected package.
