## Selected case and actual results

The short usable-state check follows the installed package delivery: open the
usual application and return with physical Home. It tests the delivery/routing
integration boundary without expanding this pass to unrelated features.

Expected: each ordinary short Home from the application opens project Home.

The standby interval and key down/up durations were not independently measured.
No AC disconnection was requested or performed; do not label this an AC cold-boot
test. In both episodes, subsequent SAM Home, profile home category and idle app
still point to project Home. Intent generation advanced from 8 to 9 across the
repeat startup. The earlier `observer_exit` with shutdown proof belongs to the
previous session, not the first Home failure. Existing successful software SSAP
Home evidence does not supersede these physical failures.

Confirmed boundary: native webOS keyfilter selected stock Home despite subsequent
active project route readback. Its internal branch, exact cause and relationship
to candidate changes remain unproved. Related #90 involved disabled intent/stopped
guardian after input-readiness failure, so no identical-cause claim or reopening
of that historical report is made.

No product fix, manual re-enable, recovery/receipt edit, reinstall, synthetic input
or diagnostic reboot was attempted. The repeat did not resolve the problem.
Stock Home is usable by owner observation; audible playback/emergency and other
remaining acceptance are not established. Raw logs, profiles, screenshots, app
inventory, addresses/serial numbers and credentials remain private.

The physical case inventory is complete for this reported path with two failures;
focused root-cause investigation is queued in #422. No new full candidate is
started per finding. A fix or new explicit maintainer disposition is needed
before proceeding, followed by affected verification; the release is not accepted.
