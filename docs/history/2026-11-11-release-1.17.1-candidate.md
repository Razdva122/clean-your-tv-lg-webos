### Why expanded permissions still break cleanup

The fixes in #510 and #514 cover Helper startup and installer setup via
`native/app/state-permissions.js`. The Stop branch of
`cytv/no_root_cleanup.py` implements its own file checks and writes.
`root-edition/build_updater.py` embeds that branch in both the Root
coordinator and its cleanup tail. Normal removal, Root-mediated removal
and the edition handoff therefore miss the recovery exercised by startup
and setup. An isolated fixture using the actual cleanup and storage code
reproduced `helper-control / unsafe-path` with a 0777 state directory and
generation. Running the existing checked recovery let the same cleanup
proceed and preserved the Stop marker inode.

The affected scope includes one checked Stop/storage operation shared by
startup, setup and all removal callers. Keep the existing ownership,
inode, group and private-key checks, reject foreign and replaced records,
and preserve Stop across repair and concurrent setup. Exercise the same
firmware-expanded fixture through explicit Stop, fresh and repeated setup,
cold boot, No-root removal, Root-mediated removal and edition handoff.
Cover retained 0777 records alongside normal metadata, wrong owners,
links and concurrent replacements. In the host recovery response, surface
a current cleanup failure before an older restart result. Record these
requirements with the consolidated QA findings before a replacement build.

by passing regression tests. The writer removes the staging link before
