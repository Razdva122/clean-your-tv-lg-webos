## Active standby: retain both attempts

**Attempt 1 — NOT ACCEPTED, telemetry failure retained.** Expected active Home
preference to survive ordinary standby/wake. Read-only evidence instead showed
disabled intent and a restored binding. The latest matching bound exit decision
recorded `observer_exit`, prior active/enabled intent, same startup session, Home
present, no failsafe and no shutdown proof. Candidate code maps observer pipe EOF
to this decision and conservatively restores Off without shutdown proof. It does
not establish why the observer exited. An adjacent active input read error,
errno `19`, lacked a transaction tag and does not prove causal ordering or caller.
No physical screen result was supplied for this attempt.

The owner reported interference from code in another application and explicitly
requested a repeat. This is a reported confounder, not a verified cause. The
first attempt remains a failure/unaccepted observation and was not erased or
converted into a pass.

**Attempt 2 — automatic start PASS; first-screen behavior NOT ACCEPTED.** Before
the separately authorized repeat, original-supervisor integrity and all three
installed candidate hashes passed again. The owner explicitly enabled through
normal Settings; a fresh active binding was captured. The owner reported the
interfering code stopped. After standby/wake, LG Channels appeared first, followed
by Clean automatically after an unmeasured delay. Owner confirmed working buttons.
Passive snapshots progressed from starting to active, and final native/intent
state was active. Audible sound was not explicitly reconfirmed in this reply.

Read-only native settings inspection showed Home Auto
Launch enabled, one Root EIM entry and remembered Root selection. The native
adapter code was unchanged from v1.5.4. These facts do not explain the delayed
foreground transition or accept its first-screen behavior. That concern remains
for triage; #171 is not declared fixed. Historical failures remain distinct from
this session's observations.

## Remaining scope

Issues #171, #202 and #207 retain unresolved original scopes; these checks do not
justify closing them. Active standby first-screen behavior remains unaccepted.
No-root, HD output, IR remote, physical language/font rendering, interrupted
installation, fresh computer provisioning and real-phone operation were not
tested. Neither normal public-feed selection nor anonymous package download was
accepted by private cached-candidate admission. Fresh supervisor `1.2.0`, general
supervisor migration, firmware blocking and compatibility with other TVs remain
untested. Full release acceptance remains draft; this record supplies bounded
observations rather than an overall shipping decision.
