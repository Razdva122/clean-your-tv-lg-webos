## Admission and transport

Initial SSH unavailability was followed by a successful connection and complete
baseline snapshot. The original oversized command then caused EOF during SSH
exec, before request delivery. Actual server banner was Dropbear 2022.83; its
[upstream command limit](https://github.com/mkj/dropbear/blob/DROPBEAR_2022.83/sysoptions.h)
is 9000 bytes, while the original bootstrap was about 19.6 kB. Short commands
worked. A private host-only zlib/base64 encoding reduced the command below 8192
bytes while preserving the exact pinned controller bytes, sanitized environment,
isolated interpreter, request-on-stdin and every original verifier/worker gate.
No executable was staged on the TV. Six existing mocks, transport roundtrip/size
checks and independent review passed before use.

The compressed read-only admission passed against the actual installed verifier:
all candidate/prior package inspections accepted, seven managed-file and three
cache-tree observations complete, and before/after hashes/inventories unchanged.
Fresh complete profiles came from the visible running Root UI, never an empty or
historical substitute. Install used the original lease, Manager and worker; only
the real launcher produced health. No fake receipt, state repair, pin replacement
or emergency clearing occurred.

## Findings kept separate

- [#202](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/202): automatic
  boot can route through explicit restore and cancel a pending System Home ticket.
  The owner reported no disable/Home input during the first update. Local mocked
  suspend -> automatic boot -> finish reproduces the captured cancellation. The
  precise on-device caller was not audited, so callback replay is a causal
  mechanism rather than a proved invocation trace. Explicit Off/emergency must win.
- [#171](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/171): matching
  active input read_error errno19 (ENODEV) -> observer_exit -> bound recovery with
  shutdown=false -> disabled Home. The binding matches the pre-cycle journal and
  recovery transaction. Which shutdown-safety conjunct failed remains unknown.
  Missing volatile health/.wake files do not disprove an earlier Off/subscriber.
  Kernel boot ID was reused while startup-session identity changed; that is not
  proof of an AC-off operation. The later boot audit already had disabled prior
  intent. No evidence permits ignoring ENODEV or weakening emergency/failsafe.
- Initial Channels during successful cold start is a requested presentation
  improvement, separate from lost intent after remote power. Current presentation
  waits for a verified first app and healthy input before optional launch. A
  separate investigation is authorized; zero initial Channels frames are unproved.
- [#203](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/203): the
  oversized SSH command is maintainer transport tooling, not a package or
  signature rejection. Its private encoding workaround did not change candidate
  product code. A maintained-tool correction remains queued with the batch.
