## Changes and guards

- Native startup: register the existing Root app only after healthy persistent
  activation, with native Home autolaunch exactly on. A root-owned receipt saves
  the prior input and uncertain add/remove phases. Restore routing before native
  cleanup; retarget only a remembered Clean input, remove only the owned entry,
  preserve unrelated selected inputs and never launch another foreground app for
  cleanup. Explicit Off, triple-Home, failsafe, package/input/guardian checks remain
  authoritative. Unavailable/unknown native startup settings retain fallback.
- Recovery: cover missing-intent orphan cleanup, disabled retry, enabled boot
  restore-before-rearm and later live legacy trials. Explicit recovery disables
  any starting intent before restoring a later bounded trial. The existing
  authenticated runtime destination and supervisor inventory/LS2 contract remain
  intact; no new permission or external endpoint is introduced.
- Update Home resume: both automatic boot fallback branches restore safely without
  writing explicit cancellation. Public Off/emergency still cancel the ticket.
- Admission: preserve exact controller bytes, pinned trust and isolated execution;
  zlib/base64 keeps the exec command below 8192 bytes, scrubs Python/Node variables
  and leaves the signed request on stdin. Oversize commands fail before submission.
- Receiver: hold a webos-service activity until stop, expiry, invalid-PIN termination
  or failed listen; keep it through receipt/read and complete late grants.
- Standby: fixed decision fields distinguish home/failsafe/session and shutdown
  proof using existing observations only. Query count, short-circuiting and fault
  policy remain unchanged. ENODEV is not interpreted as proof of normal shutdown.
