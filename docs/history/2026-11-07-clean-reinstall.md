# Verified clean Root reinstallation — 2026-11-07

Source/model verification for the unpublished 1.10.0 candidate. This record does
not publish a private device report or establish release acceptance.

## Failure and bounded correction

Practical removal retains minimal component fences and historical request
records. The old host path treated `cancellation-admitted` as an unfinished
installation, while Restore tried to execute the already retired driver.
Current inspection now revalidates the complete removal proof under the original
ownership mutex. A proved removed state permits ordinary Root setup; Restore
acknowledges that LG routing is already restored. A blocked inspection remains
a typed failure rather than a missing-key exception.

The existing coordinator performs the new-install lease handoff. Component
fences move into the existing installation evidence directory, preserving their
inodes and original request tombstones. The new private
`component-fences-plan-<operation>.json` records original directory identities,
old clean lease and successor lease before the first move. A retry validates
both moved and remaining directories before continuing the same request.

The worker seals its existing durable snapshot with bottom-up directory fsync.
It preserves the original temporary upload. Clean readback accepts a temporary
product upload only when its complete checked inventory matches that current
payload; unknown, changed and additional entries still block. Current coordinator
copies require the corresponding exact checked code inventory and hashes.
Read-only status polling is exempt from live-worker rejection only for the exact
current interpreter, code copy and fixed argument forms. Package-changing,
resume, worker and unknown arguments remain blocked. A bounded wait for the
spawning parent does not replace the final process proof.

Read-only inspection has no full product payload. Its JS inventory helper is
therefore selected from the currently executing checked coordinator directory,
verified against its manifest before execution. Normal support launches disable
bytecode writes. Stale volatile support or a live old worker yields the existing
restart instruction; neither a changed error format nor standby counts as a
verified restart.

Root setup reads apps and external inputs with the existing fixed Root catalog
reader over authenticated SSH. Its catalog is bounded, deduplicated and validated
before personalization, including embedded icons and profile-compatible colours.
Root requires no SSAP pairing for this read. No-root retains its existing SSAP
pairing, retry and inventory behavior. No additional endpoint, permission grant,
Helper release, observer or updater destination is introduced. C1 Beta keeps its
fresh-install-only guard; this correction does not enable native reinstallation.

## Verification and boundaries

- Regressions reproduced the retained-fence refusal, read-only payload absence,
  stale support, interrupted fence movement and status-polling race before fixes.
- Current clean-removal module: 50 tests passed. The existing complete driver
  suite passed 51 tests; six focused worker durability checks passed after the
  submission correction. These are filesystem/process models, not TV acceptance.
- Host operations/CLI/shared regression pass: 148 tests passed before the added
  Root SSH inventory adapter. Its final affected CLI, checks, inventory and TV
  pass ran 72 tests successfully, including unchanged No-root SSAP retry cases.
- Independent review approved the final ownership/cleanup, read-only support and
  Root inventory changes with no outstanding Critical/Important findings.
- Focused payload verification preserves all TV IPK bytes, published Helper0.7.4
  and the native installer support utility. Only current installer support and
  manifests change. Final release packaging still requires one replacement full
  candidate after the completed fix batch is integrated.

Installation guides and all thirteen localized guides already scope pairing to
No-root and Root setup to SSH; no new translated action is needed. Existing
restart and connection-loss messages are reused. Original installation reports
remain unresolved unless their own diagnosis and reporter evidence establish a
fix. Pristine Developer Mode, physical phones and AC cold-start results must not
be inferred from these source checks. Do not mark the main release ready until
its exact selected artifacts and affected physical results are recorded.
