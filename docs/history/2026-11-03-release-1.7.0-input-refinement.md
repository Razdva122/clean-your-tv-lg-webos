## Preview and missing status labels

The owner selected Liquid Glass. Preview was initially disabled; enabling the
existing switch made native HDMI preview work. The maintainer then explicitly
selected default-on preview for the release, retaining saved Off. Known native
sound/HDR limitations remain documented; no global mute/HDR setting is changed.

All input status fields later had empty text and zero text height, while CSS
remained visible. A query from the Root WebApp returned a denied-method reply
for EIM getAllInputStatus; the root CLI could read the input inventory. This
isolates a permission/data path failure, not a CSS conclusion or proof that the
preview toggle erased state. Raw inventories and diagnostics remain private.

The focused correction uses the existing Root listApps endpoint with the exact
read selector `{inputs:true}`. It authenticates the Root app, requires root UID,
uses a fixed bounded native query, sanitizes the response and coalesces reads.
The legacy app-list response, LS2 grants and original-supervisor permission-plan
hashes remain unchanged. Root reads are explicit foreground snapshots; failures
return unknown status. No polling, automatic retry or continuous hot-plug claim
is introduced. No-root keeps its current direct query path pending device QA.
