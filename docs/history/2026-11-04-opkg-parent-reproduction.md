# Real opkg extraction and No-root parent directories — 2026-11-04

## Decision and limits

Offline maintainer research for [#307](https://github.com/Razdva122/clean-your-tv-lg-webos/issues/307)
reproduced loss of the service subtree using real, unmodified opkg extraction
code. Adding parent directory entries prevents that failure in this environment.
This establishes an archive compatibility defect, not the identity/behavior of
the owner's retail firmware or a completed fix on their TV. No TV was contacted
or changed, and no new installation is requested. This record contains local
package/source results, not another user's installation report.

The separate [diagnostic PR #309](https://github.com/Razdva122/clean-your-tv-lg-webos/pull/309)
preserves known failure categories; this packaging change does not depend on it.
The denied-status/original-transaction [recovery limitation](../development/NO-ROOT-TERMINAL-HANDOFF.md)
remains unresolved. Neither successful local extraction nor opkg exit 0 permits
clearing a journal, retrying an operation or inferring service registration.

## Inputs and actual execution

- Published Helper 0.6.22 from [v1.7.1](https://github.com/Razdva122/clean-your-tv-lg-webos/releases/tag/v1.7.1):
  SHA-256 `0e8477113fd8afc57b5f3bfc7271a3b7de99dcce2fb2516d7e386eff06ec00cf`,
  verified against published checksums; 82 tar entries and 72 regular files,
  including eleven service files.
- Official historical [opkg 0.1.8 archive](https://downloads.yoctoproject.org/releases/opkg/opkg-0.1.8.tar.gz),
  SHA-256 `ff94bf30bd662d49c4b5057e3a0818d062731adaa555d59abd677ec32a3c1c60`,
  matched to its publisher's `.sha256` file. This is a comparison implementation,
  not an identified retail webOS binary.
- A separate Linux amd64 container running under the local arm64 Podman VM.
  Base image digest is pinned in the lab recipe. This is not ARM32 ABI acceptance.
  Build uses GCC 12 with `-fcommon` for old C common symbols; extraction source is
  unchanged. Network/signature features are disabled in this offline lab build.
- A thin C entry point calls **`pkg_extract_data_files_to_dir` in the compiled
  opkg library**. It only supplies the package filename, destination and logger
  configuration. No recursive-directory model substitutes for the extractor.
  Execution has no network, host mounts or writable image root; all destinations
  are new directories under container tmpfs.

The ordinary 0.1.8 CLI stops earlier because it requests `./control`, while this
IPK names that entry `control`. The library's real data-extraction entry point
reads the original ar IPK without changing its wrapper/control/data bytes.
This lab does not exercise the full CLI installation path, LG's installer
wrapper, LS2 registration or retail transaction semantics.

## Controlled matrix

The one-parent control prepends only `usr/palm/services`; all 82 original tar
records and their bytes remain intact. The corrected variant is generated by
the changed production `cytv.package.ipk`, with all five shared parents enabled.
It preserves every original file byte, original record metadata and control
archive; it adds five `root:root 0755` directory records, for 87 entries total.

| SDK tree before extraction | Original | One services parent | Production correction |
| --- | --- | --- | --- |
| applications/packages exist, services absent | 61 files, 0 service files | 72 files, 11 service files | 72 files, 11 service files |
| All three containers exist | 72 files, 11 service files | 72 files, 11 service files | 72 files, 11 service files |
| No SDK ancestors exist | 0 files | 0 files | 72 files, 11 service files |

The original failing cases log missing-directory errors but return **0** from
the opkg extractor. The correction is checked by file counts, bytes and installed
mode/UID/GID, not by exit code alone. Corrected cases must produce no error output.

An additional real OpenWrt `opkg-lede` CLI build at
`80503d94e356476250adaf1f669ee955ec26de76` reproduced the same matrix. It accepts
gzip/tar outer packages rather than our ar wrapper, so that supplementary
experiment changed only the outer wrapper identically for all variants. Inner
control/data archives were unchanged. It is not a direct original-IPK install.
Its optional upstream test executable failed to link due to duplicate
`opkg_state_changed`; building the unchanged CLI with `BUILD_TESTS=OFF` succeeded.

## Product change and release impact

The No-root app/service builder explicitly enables all required parents before
their descendants. Home personalization enables them too, so rebuilding the
archive with the selected inventory cannot discard the correction. Timestamps,
ordering and gzip remain deterministic. Existing file bytes, executable modes,
Helper state `5999:5000/0770` and Home shared state `5999:5000/02770` are retained.

Shared parents use fixed `0:0/0755`, never build-host identities or `0777`.
**This can change attributes of an existing shared SDK directory:** opkg applies
archive owner/mode even when the directory already exists. That effect requires
separate-device retail acceptance before release, including coexistence with
other sideloaded apps. It is not claimed to preserve unknown vendor permissions.
Root builders/default archives and Root personalization retain the owned-leaves
policy and do not receive shared parents. Rollback validators/authority remain
unchanged; ordinary Root package/rollback checks remain required.

No published IPK is rewritten and no component version is selected here. Future
integration must rebuild affected No-root Helper, Home and updater IPKs and
embedded desktop/Android payloads, with appropriate component version bumps and
release manifests. A retained published Helper baseline is not retrofitted.
The extra archive records also invalidate prior identical-layout Helper rollback
evidence: the future candidate needs a new rollback-compatibility acceptance
record. Do not weaken or bypass that validator to reuse an old approval.
Frozen candidate #281 and its selected build are untouched; queue this work for
the following cycle. Physical installation, Home routing, sound, standby, cold
boot, OTA and rollback remain untested on the affected retail firmware.

## Reproduce without a TV

Use the existing local Podman service; the lab creates no host mounts. Prepare a
build context containing only the listed public inputs, never the whole checkout:

```sh
opkg307_lab=$(mktemp -d)
cp tests/cytv/opkg/Containerfile tests/cytv/opkg/extract.c tests/cytv/opkg/verify.py "$opkg307_lab/"
cp cytv/package.py "$opkg307_lab/package.py"
curl -fL https://downloads.yoctoproject.org/releases/opkg/opkg-0.1.8.tar.gz -o "$opkg307_lab/opkg-0.1.8.tar.gz"
curl -fL https://github.com/Razdva122/clean-your-tv-lg-webos/releases/download/v1.7.1/com.local.nativehome_0.6.22_arm.ipk -o "$opkg307_lab/original.ipk"
podman build -t localhost/cytv-opkg307:verification "$opkg307_lab"
podman run --rm --network=none --read-only --cap-drop=all \
  --cap-add=CHOWN --cap-add=FOWNER --cap-add=DAC_OVERRIDE \
  --tmpfs /tmp:rw,size=128m localhost/cytv-opkg307:verification
```

The recipe/script verify source and IPK SHA-256. The script requires the nine
expected extraction results, byte/metadata preservation and corrected installed
attributes. Added capabilities exist only inside this disposable container to
honor the real numeric state-directory ownership and read it back. Do not run
the experiment against a TV, host root or existing installation.
