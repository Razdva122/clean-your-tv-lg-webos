## Identity and historical browser predecessor

The web predecessor is verifiable **inside the same ecklf/lg-luma repository**, rather than inferred from a similarly named project. [v1.1.1](https://github.com/ecklf/lg-luma/releases/tag/v1.1.1), published 2026-10-21T13:04:00Z, points to **da3b8229e51b9494b98381f309d80f5e5dd8f6be**. Its [appinfo](https://github.com/ecklf/lg-luma/blob/v1.1.1/appinfo.json) says `type:web`, `main:index.html`, ID `com.luma.launcher`, resolution 1920x1080. Its [README](https://github.com/ecklf/lg-luma/blob/v1.1.1/readme.md) and [package.json](https://github.com/ecklf/lg-luma/blob/v1.1.1/package.json) document React/TypeScript, local browser storage, Chromium 108+/webOS 24–26 target, elevated Homebrew inventory, manual Input Hook Home routing, 25-second cold-boot autostart, and per-input On/Off/Auto. This older target must not be reused as the native release's compatibility boundary.

[PR #10](https://github.com/ecklf/lg-luma/pull/10) is the native rewrite, merged 2026-10-22T10:09:19Z. [v2.0.0](https://github.com/ecklf/lg-luma/releases/tag/v2.0.0) published at 10:20:04Z, commit **442a04ebefe3eee50e1b60c1004cb080a5ccb157**, has `com.ecklf.luma_2.0.0_arm.ipk`. The native [README](https://github.com/ecklf/lg-luma/blob/v2.8.5/readme.md) explicitly says the new native ID installs alongside the old browser ID and former native prototypes; browser preferences are not migrated.

**`ecklf/luma` returned HTTP 404** from the public GitHub API. Evidence does not establish it as a previous canonical repository name or redirect. Describe the historical web version as *ecklf/lg-luma v1.x*.

API metadata confirms [donnes/luma](https://github.com/donnes/luma) is a fork whose `parent` and `source` are both `ecklf/lg-luma` (created 2026-10-20). [PR #6](https://github.com/ecklf/lg-luma/pull/6) offered `donnes/luma:main` to upstream and was closed **unmerged**. Fork features must not be credited upstream. [luma-home-tv/native-home](https://github.com/luma-home-tv/native-home) is a separate non-fork repository, created 2026-10-14, whose official README describes an experimental dashboard on attributed PlxNative; it is not this Luma's native rewrite.

## Additional shipped improvements useful in a roadmap discussion

- **Black/partly black screen on a no-op arrow press:** v2.8.2 / **d5f778c** fixed an invalid damage pixel outside the EGL surface. [Release](https://github.com/ecklf/lg-luma/releases/tag/v2.8.2), [PR #74](https://github.com/ecklf/lg-luma/pull/74). This is a shipped implementation claim; no issue-level device acceptance was independently established here.
- **Inventory empty/error early in boot:** v2.8.5 contains PR #81/**945598a** retrying initial inventory five times at 2-second intervals, and #82/**2a03caa** reading directly as root Home before HBC starts. Changelog headings include 2.8.4, but **no v2.8.4 release record/tag was retrieved**. Credit public delivery to v2.8.5. [Release](https://github.com/ecklf/lg-luma/releases/tag/v2.8.5).
- **Navigation/rendering speed:** v2.8.1 release notes claim Home focus 39→60fps, Recents 37→48fps, and first Apps worst frame 179→40ms on one webOS5 TV. These are specific contributor measurements, not comparative CYTV benchmarks or cross-model guarantees. [Release](https://github.com/ecklf/lg-luma/releases/tag/v2.8.1), [changelog](https://github.com/ecklf/lg-luma/blob/v2.8.5/CHANGELOG.md).

## Coverage limitations and reporting cautions

- All actual upstream issues were covered; selected PRs were deep-read, not all 84 PRs. The linked external fork PR (`wpelle/lg-luma#1`) duplicates upstream #59's contribution and was not independently deep-read; external Glasshouse #946 is a cross-project discussion, not an extra upstream Luma issue. The Luma conclusions use upstream #59/#38.
