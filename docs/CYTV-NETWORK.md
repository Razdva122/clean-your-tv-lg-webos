# Where Clean Your TV connects

[Русский](CYTV-NETWORK.ru.md) · [TV privacy settings](PRIVACY.md) · [DNS controls](PRIVACY-DNS.md)

For a local setup, use a bundled theme, leave **Settings → Weather** off and keep the theme and wallpaper receivers closed. Opening **Home settings** can still check GitHub for available CYTV updates on editions with a compatible updater. Launching a streaming app also starts that app’s own network activity.

## From the computer or Android installer

| When | Destination and information |
| --- | --- |
| Getting CYTV or checking the desktop/console installer version | Downloads and release metadata come from GitHub. On a fresh install the desktop/console entry point checks `api.github.com` for the latest stable release, then reads that tag’s `BUILD-INFO.json` from GitHub Releases. The request identifies CYTV as the client. If the check fails, the bundled installer can continue. Choosing a newer release opens its download page. Android’s installer bridge skips this desktop version check. |
| Supplying Python for a supported Root installation | When the TV needs the private runtime and the installer lacks a verified cached archive, the installer fetches the pinned ARM build from the `astral-sh/python-build-standalone` GitHub release, checks its size and SHA-256, then transfers it to the TV. GitHub may redirect downloads to its asset hosts. |
| Finding a TV | Automatic discovery sends SSDP multicast to `239.255.255.250` on UDP 1900. To obtain the friendly name it may fetch the replying TV’s local HTTP description at its advertised port. Entering an address or reusing a saved profile skips the broadcast. |
| Connecting and installing | The installer sends packages and maintenance commands to the chosen TV over SSH. Defaults are TCP 9922 for Developer Mode and 22 for existing root SSH, including No-root through root SSH. Developer Mode’s Key Server supplies the encrypted SSH key at `http://<TV>:9991/webos_rsa`. Use a trusted LAN, check the TV’s identity and the displayed SSH fingerprint before trusting it. |
| Pairing and reading the Home inventory | When needed, SSAP connects to `wss://<TV>:3001`. Approve the TV pairing prompt. The installer can read installed app names, icons and inputs to populate Home. Relative icon paths can be read from the same TV via HTTPS 3001 or HTTP 3000. Developer Mode Debloat can request a separate pairing with permission to write the selected LG settings. |

**Debloat** reads and writes the selected settings on the TV. For supported LG settings with a readable original value, the installer records that value in the private profile for optional restoration. An LG setting can change the traffic LG software generates. The Debloat operation itself uses the local TV connection. [Installer settings](development/INSTALLER-SETTINGS.md)

The computer keeps per-TV connection profiles, pinned SSH host keys, pairing keys and recovery records in its CYTV data directory. Android uses app-private storage. Save diagnostic exports separately and keep recovery data while an operation is pending. The SSAP connection uses the TV’s self-signed certificate. The desktop data locations and connection options are in the [CLI guide](CLI.md). Implementation details are in [discovery](../cytv/discovery.py), [SSH and key retrieval](../cytv/transport.py), [pairing and icons](../cytv/tv.py), [installer version check](../cytv/installer_update.py) and [runtime download](../cytv/python_runtime.py).

## From the TV

| Feature | When it connects and what you can change |
| --- | --- |
| Home and remote control | Root controls Home through local webOS services. On No-root, the Helper can connect back to the TV’s own network address on 3001 to observe foreground and power state with its pairing key. Tiles, layout and optional app-launch counts for sorting stay on the TV. Opening a tile gives the selected app control. [Helper connection](../native/app/screen-watch.js) · [App library](../launcher/app-library.js) |
| Weather, both editions | Fresh Home has weather off. With weather on, **City → Automatic** uses `get.geojs.io` to estimate a city from the public IP, refreshing at most daily. **City → Manual** sends the search text and language to `geocoding-api.open-meteo.com`. It can also look up a city ID for a localized name. Both location modes send the selected coordinates for a forecast to `api.met.no` or `api.open-meteo.com`. The automatic **forecast provider** can try the other provider on failure. Selecting a single provider restricts forecast requests to that provider. Turn weather off to stop requests. Home keeps the city and preferences locally. Forecast caches can supply data up to six hours old. [Weather controls and cache](development/WEATHER.md) · [Request code](../launcher/weather-data.js) |
| CYTV updates and rollback | A supported updater can check for offers when you open Home settings, open **Software updates** or choose **Check**. GitHub receives requests for release feeds, signatures and, when you install, the selected packages. Asset redirects can use `release-assets.githubusercontent.com` or `objects.githubusercontent.com`. The public files requested can identify the edition, component or display variant. The updater verifies signed metadata and package hashes. Installation requires a separate action. Compatible rooted TVs use the System Updater, including supported No-root installs through root SSH. Current No-root Developer Mode installs update from the computer. Rollback uses retained package and profile evidence on the TV. Keep it intact for recovery. [Update paths](UPDATES.md) · [System update checks](../launcher/system-updates.js) · [Root download policy](../root-edition/updater/fetch.js) |
| Themes, both editions | Built-in themes and already downloaded versions can run offline. Opening **Theme showcase** or refreshing it requests the project’s main revision from `api.github.com`, then its catalogue and previews from `raw.githubusercontent.com`. Downloading a theme loads the selected author’s commit-pinned files. Using a short theme ID sends that ID to `da.gd` to resolve it. A supported full GitHub URL avoids the short-link lookup. Home caches installed themes on the TV. [Theme controls](THEMES.md) · [Link resolution](../launcher/theme-data.js) |
| Personal wallpapers and local theme transfer | Opening **Receive from computer** or **Upload from phone** starts a temporary HTTP receiver on the TV, normally TCP 8879. A computer or phone on the LAN sends the theme or picture using the displayed PIN. The session expires after ten minutes or can be closed on the TV. The phone upload page crops and converts images locally. Confirm **Apply** on the TV. Native wallpaper and supported screensaver playback use TV-only loopback HTTP at `127.0.0.1` on an allocated port. [Receiver](../theme-receiver/core.js) · [Wallpaper handling](development/WALLPAPERS.md) · [Screensaver transport](../screensaver/transport.js) |
| LG Developer Mode renewal | An opt-in feature for No-root with Developer Mode. When enabled it schedules local checks and sends the TV’s existing Developer Mode session token to `developer.lge.com` over HTTPS to check time remaining. Within seven days of expiry it can request an extension and read back the result. Disable auto-renewal in Home settings to stop those scheduled requests. LG controls the official timer. Root and No-root through root SSH do not need this renewal. [Renewal logic](../renewal-service/renewal.js) · [LG request](../renewal-service/transport.js) |
| LG firmware updates | The optional Root switch reads or writes Homebrew Channel’s local `blockUpdates` preference. Homebrew applies it at a full TV restart. It can also block security updates and can survive CYTV removal. To reverse it, turn the switch off and restart through Homebrew Channel. Its displayed state reports the saved preference. LG controls firmware delivery. [Firmware control](LG-FIRMWARE-UPDATES.md) |

If you install CYTV from Homebrew Channel, that app fetches its configured repository and installer package. The CYTV Installer for Homebrew carries the project installation payload for local setup. Repository refreshes in Homebrew and GitHub feed checks by the installed CYTV updater are separate actions. [Installation methods](INSTALL.md) · [Homebrew payload](../homebrew/payload.py)

## Reports, QR codes and external links

**Save diagnostic report** writes an already-redacted JSON export locally. It can include the TV model, readable firmware/webOS and component versions, installation stage, checks and error categories. Credentials, TV addresses and personal app inventories are excluded from the standard export. On desktop you can copy an editable issue draft, open GitHub with its proposed title and attach the saved file yourself. Saving alone publishes nothing. [Feedback guide](FEEDBACK.md) · [Report builder](../cytv/diagnostics.py)

In the on-TV Homebrew installer, scanning the report QR opens the project’s GitHub Pages support page. The compact report travels in the URL fragment after `#`. The browser reads it locally, so the initial HTTP request for the page omits it. **Download JSON** saves a copy on the phone. Opening the prefilled GitHub issue sends the draft title and report body to GitHub at that point. Submitting the issue publishes it. Treat the QR and its complete URL as copies of the compact report. [QR format](../homebrew/app/report-format.js) · [Support page](../website/src/pages/support/homebrew.astro)

The public project site uses GitHub Pages and keeps its language selection in the browser. Following a release, help, LG sign-in, credits or author link contacts the destination you open. External services see the request’s source public IP, timing and requested resource. Their logging and retention depend on their own policies. The reviewed CYTV paths store the Home inventory and diagnostic records locally. Sharing a report is an owner action. Actual traffic from LG firmware, third-party TV apps, the router and the browser depends on your setup. [Website implementation](../website/src/layouts/Site.astro) · [TV privacy guide](PRIVACY.md)
